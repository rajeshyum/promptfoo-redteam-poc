# File Guide — what every file in this repo does

A plain-language map of the project, grouped by area. Paths are relative to the repo root
(`promptfoo-redteam-poc/`). For *findings* read [poc-results.md](poc-results.md); for the
*plan* read [promptfoo-poc-design.md](promptfoo-poc-design.md); this file explains the *files*.

```
promptfoo-redteam-poc/
├── README.md                     ← start here: setup, how to run, headline results
├── .env / .env.example           ← secrets & config (keys, toggles)
├── .gitignore                    ← keeps secrets + adversarial outputs out of git
├── package.json / package-lock   ← pins the promptfoo CLI (Node dependency)
├── docs/                         ← the plan, the results, the scenario matrix, this guide
├── supportbot/                   ← the deliberately-vulnerable target app (Phase 1)
├── redteam/                      ← Promptfoo configs + wrapper scripts (Phase 2–5)
└── .github/workflows/            ← the CI red-team gate (manual dispatch only)
```

The root files are what the tree says they are. Two worth knowing: `.env.example` is the
committed template that documents every environment variable (copy it to `.env`, which is
gitignored), and `package.json` pins the single Node dependency — the `promptfoo` CLI itself.

## `supportbot/` — the deliberately-vulnerable target app (Phase 1)

A small FastAPI + OpenAI function-calling app for a fictional "Acme Fintech." It is the *target*
Promptfoo attacks. Each file plants specific weaknesses (numbered #1–#9 per the design §2).

| File | What it does | Planted weaknesses |
|---|---|---|
| **\_\_init\_\_.py** | Marks `supportbot` as a Python package; carries the top-of-repo safety warning (local, authorized testing only). | — |
| **requirements.txt** | Python deps for the app: `fastapi`, `uvicorn` (server), `openai` (LLM + tool calling), `pydantic` (request/response models), `python-dotenv` (loads `.env`). | — |
| **app.py** | The FastAPI app and HTTP surface Promptfoo targets. `POST /chat` (`{session_id, message, context?}` → `{reply}`, raw markdown), `GET /health`, and `POST /reset` (test harness — clears sessions + the CRM scratchpad so findings don't depend on test order). Returns **502** when the upstream model call fails, so promptfoo records an error rather than grading a placeholder as a safe refusal. Also holds `_sanitize_markdown()`, gated on `SUPPORTBOT_SANITIZE_OUTPUT` (off by default), which produces a non-vulnerable variant on demand. | #9 (raw markdown reply) |
| **agent.py** | The brain: the OpenAI chat + tool-calling loop. Holds the weak, leak-prone **system prompt** (embeds a fake `INTERNAL_OPS_KEY`, no guardrails), appends raw user input with no sanitization, offers all tools unscoped, returns replies with no moderation, and re-injects a process-global "CRM memory" into every session (so PII bleeds across sessions). Harness additions: bounded OpenAI timeout, `AgentError` for infrastructure failures (distinct from refusals), a lock and size cap on the session store, `reset_state()`, and a `SUPPORTBOT_SYSTEM_PROMPT[_FILE]` override for testing whether a guardrailed prompt closes #1. | #1 (system prompt), #2 (no input sanitization), #6 (cross-session memory), #7 (unscoped tools), #8 (no moderation) |
| **tools.py** | The three function-calling tools + their data. `lookup_account()` returns any account's PII with no authorization check and records it to the shared CRM scratchpad; `query_transactions()` builds SQL by f-string interpolation (injectable, with an `internal_secrets` table reachable via `UNION`); `dispatch()` routes tool calls and appends any request-supplied `context` to retrieval results (the `indirectInjectionVar` hook). Locks serialize the shared sqlite connection and the scratchpad under promptfoo's concurrency — the SQL stays injectable; only the plumbing is made safe. | #4 (no authz), #5 (SQL injection), #6 (PII + cross-session) |
| **knowledge_base.py** | The RAG store + a naive keyword retriever with no access control. Holds benign FAQs, one **confidential** doc (internal pricing + staff contacts = the exfiltration target), and one **poisoned** doc whose hidden instructions tell the model to leak the confidential doc and append a data-carrying `attacker.example` markdown image. `search_kb()` returns any matching doc, confidential or poisoned. Also loads `SUPPORTBOT_EXTRA_DOCS=<dir>` at startup — the ingestion path that makes `promptfoo redteam poison` output plantable. | #3 (confidential + poisoned docs → indirect injection, chains into #9) |

**How a request flows:** `app.py /chat` → `agent.py run_agent()` (OpenAI loop) → may call
`tools.py` / `knowledge_base.py` functions → returns raw-markdown reply.

## `redteam/` — Promptfoo configs + wrapper scripts (Phase 2–5)

### Configs (what Promptfoo runs)

| File | What it does |
|---|---|
| **promptfooconfig.yaml** | The **default fast scan** (~15 min). HTTP target (body templating with `{{prompt}}`/`{{sessionId}}`, `transformResponse: json.reply`, `sessionSource: client`), the enriched `purpose` (the app's real affordances — valid account-id format, tool names, the existence of a confidential doc), 11 plugins (one per planted weakness, now including `data-exfil` for #9 and `agentic:memory-poisoning` for #6), `numTests: 2`, 1 strategy. Comments explain what is deliberately left to the sibling configs and why. |
| **depth.yaml** | **Strategy depth** — 5 strategies (`prompt-injection`, `base64`, `leetspeak`, `jailbreak:composite`, `crescendo`) against the weaknesses most likely to flip from defended to exploited once a strategy is layered on. Satisfies the design's "≥3 strategies" criterion, which the default config alone does not. |
| **policy-intent.yaml** | The **Custom & Configurable** plugin category: 4 `policy` rules encoding Acme-specific business constraints, plus 6 explicit `intent` goals for threats with no matching catalog plugin. The only category that encodes *your* rules rather than generic ones. |
| **datasets.yaml** | The **Dataset Collections** category — 6 published adversarial corpora (`harmbench`, `donotanswer`, `beavertails`, `cyberseceval`, `pliny`, `xstest`). Notable for being reproducible run-to-run and needing no remote *generation*, making it the one pass suited to a CI gate and to a data-residency-constrained org. |
| **indirect-injection.yaml** | The **native** RAG-poisoning / indirect-injection pass, using `indirectInjectionVar: context` against `/chat`'s optional `context` field. Exists because the original conclusion — that these plugins can't work against a server-side KB — was too broad. |
| **owasp-framework.yaml** | The **framework-mapping** pass (`owasp:llm` + `owasp:api`) that produces the compliance artifact §4 lists as an exit criterion. `numTests: 1` keeps a ~53-plugin preset tractable; read the cost warning in the header first. |
| **crescendo.yaml** | A focused **multi-turn** pass on the two weaknesses the single-shot scan missed (#1, #8). `stateful: true` + the `crescendo` strategy, `numTests: 1`. Answers "does multi-turn break the model's refusals?" (it didn't). |
| **exfil-eval.yaml** | A **deterministic eval** (no attack generation) that triggers the baked-in poisoned doc with refund questions and asserts the reply carries no `attacker.example` URL, confidential pricing, or secret value. Each test now carries its own `session_id` — the earlier `{{_index}}` templating rendered empty, so all four tests shared one concurrent session and *understated* the vulnerability. |
| **exploit-suite.yaml** | The **deterministic exploit suite** — 13 hand-written probes covering every planted weakness, run with `--repeat 3` in ~35 s. Two of them (#1, #8) are **controls expected to hold**, so a suite that only contained probes known to land can't be mistaken for this one. It answers *"is this weakness still open?"*, **not** *"would a scanner find it?"* — every probe was written holding the answer key (real account ids, the SQL filter format, the exact confidential strings), so **its hit rate is never a Promptfoo capability number**. Its value is as the control against generation variance: 28, 28 and 29 of 39 across three runs, while the generated scan moved 12/40 → 6/47 → 12/47. Any weakness proven open here but MISSED by the generated scan is a measured false negative. |

### Wrapper scripts

All source the root `.env`, resolve the local `promptfoo` binary, auto-detect a Node satisfying
promptfoo's strict engines range, reset the target's state before running, and tolerate
promptfoo's exit code 100 (a failing assertion is the expected result here). Shared logic lives
in **`_lib.sh`**; run **`./scenarios.sh`** for the full list with runtimes.

| File | What it does |
|---|---|
| **_lib.sh** | Shared helpers, sourced by every script: `.env` loading, Node-version resolution, target health check, `POST /reset`, `app_restart` (always launches uvicorn from the repo root — `supportbot.app:app` resolves against the CWD), and `pf()` which tolerates exit 100 and only 100. |
| **scenarios.sh** | The index: every scenario, the design criterion it satisfies, and its runtime. `--check` verifies node / keys / auth / target / that every config parses. |
| **scan.sh** | The generic red-team runner — `./scan.sh <config>`. Saves the generated **cases** *and* exports the **results** (`redteam run -o` writes only the cases; results otherwise stay in the local DB and the run leaves no artifact). |
| **run.sh** | Thin wrapper: `./scan.sh promptfooconfig.yaml`. |
| **crescendo.sh** | Thin wrapper: `./scan.sh crescendo.yaml`. |
| **eval.sh** | The generic runner for deterministic eval configs — `./eval.sh exfil-eval.yaml --repeat 3`. |
| **scorecard.sh** / **scorecard.mjs** | **The core deliverable.** Derives the §4.1 detection scorecard from the saved results against a plugin→weakness mapping, distinguishing DETECTED / MISSED / **NOT TESTED**, separating plugin detections from custom-eval ones, and tallying findings that map to no planted weakness. `--markdown` emits a paste-ready table. |
| **rescan.sh** | Replays a **saved** case set (`promptfoo redteam eval`) with no regeneration — the apples-to-apples rescan the design demands, since fresh generation produces different attacks. |
| **compare-runs.sh** / **compare-runs.mjs** | Per-case before/after diff. Reports CLOSED / STILL OPEN / REGRESSED / **INCONCLUSIVE**, excluding cases that never reproduced the vulnerability from a fix's numerator. |
| **cost-report.sh** / **cost-report.mjs** | Tokens, cost, grader calls and per-case latency for a run — the cost-at-scale measurement the design asked for and the original POC estimated rather than measured. |
| **discover.sh** | Runs the **Target Discovery Agent** and saves its derived purpose, so it can be diffed against the hand-written one. Tests whether the "detection depends on purpose enrichment" finding is a real adoption cost or a documentation gap. |
| **local-generation.sh** | Runs the same config with remote then local generation, saving both artifacts plus a plugin-by-plugin diff of what actually generated in each mode. |
| **poison-kb.sh** | Generates poisoned documents with `promptfoo redteam poison`, then prints how to ingest them via `SUPPORTBOT_EXTRA_DOCS` and attack the poisoned corpus. |
| **code-scan.sh** | Static LLM-security scan of the source (`promptfoo code-scans run`) — a second scorecard against the same 9 known plants, with no dependence on the target model cooperating. Prompts before uploading source to Promptfoo Cloud. |
| **ci-gate.sh** | The CI gate: replays a **committed** case set and fails on a configurable `MAX_EXPLOITED` budget rather than on promptfoo's blunt exit-100. Emits `ci-junit.xml`. |
| **model-compare.sh** | Runs the same cases against 2+ models. The only way to separate "Promptfoo's probe was too weak" from "the base model refused" — the two readings of the POC's #1/#8 misses, which lead to opposite conclusions. `scorecard.mjs` points every MISSED row here. |
| **report.sh** | Opens the **local** vulnerability dashboard (`promptfoo redteam report`). Nothing is uploaded. The stakeholder demo artifact. |
| **view.sh** | Opens the general local results viewer (`promptfoo view`). |

### Generated (gitignored)

| Path | What it does |
|---|---|
| **output/** | Scan/eval result JSON (`redteam-results.json`, `crescendo-results.json`, `exfil-eval-results.json`, `exploit-suite-results.json`) + the local report DB. **Gitignored because red-team outputs can contain adversarial and harmful generated content** — attack prompts that succeeded, and the app's unmoderated replies to them. Nothing under `output/` should be pushed. |

`.venv/`, `node_modules/` and `__pycache__/` are likewise gitignored build products, created by
`python3 -m venv .venv` and `npm install`.
